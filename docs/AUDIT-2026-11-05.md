# IT Toolbox 架构与缺陷审计报告

- 审计日期：2026-11-05
- 审计对象：`it-toolbox` v1.6.0（144 个工具，Cloudflare Pages Functions 全栈）
- 证据来源：生产环境 `https://ittool.wort.uk` 实测 + 源码静态检查

---

## 1. 结论

**不需要全量重构。** 现有分层（React 前端 / `packages/core` 纯函数 / Hono Pages Functions）方向正确，144 个工具的注册与懒加载机制可用。问题集中在**边缘运行时约束、上游超时治理、元数据双源与 API 契约**四处，属于局部改造，不是架构选型错误。

建议顺序：

1. 先修 P0（AI 502、SSL 检测挂死）——本轮已修，待部署验证。
2. 再补 P1 的超时、解析与契约问题——本轮只修与 502 直接相关的部分。
3. 结构性重构（R1–R4）在 P0/P1 稳定后按需推进，不建议与故障修复同批上线。

---

`node scripts/smoke.mjs https://ittool.wort.uk`：**11/12 通过**。唯一失败项 `ai-regex` 在 21.1s 返回 `502 text/html`，响应是 Cloudflare 的 "Host Error" 错误页，不是业务 JSON。

| 接口 | 结果 |

## 3. P0 缺陷（已复现，本轮修复）

### P0-1 AI 接口边缘 502

**现象**：10/12 接口在 13–19s 返回 Cloudflare HTML 502，前端只能显示"服务返回非 JSON 响应"。

**根因**：四重叠加。

1. `functions/api/routes/ai.ts` 单模型超时 12s、总预算 25s，降级链最长可跑到 25s，超过实测可用的边缘请求窗口（18.3s 可返回、21.1s 已失败）。
2. 超时后仍继续调用下一个（通常更慢的）模型，使总耗时进一步放大。
3. 模型返回非 JSON 时只做 `JSON.parse(去掉代码围栏)`，直接抛错转 500；`json-schema` 的 500 即由此产生。
4. 超时后直接返回会让边缘取消仍在执行的上游 AI 子请求，业务 JSON 被 Cloudflare 的 HTML 502 覆盖。第二轮验证（6s 超时）失败点前移到 6.5–8.2s；第三轮登记 `waitUntil` 无效，证明问题不是"子请求被遗弃"，而是"提前返回"本身。

**修复**：取消 JS 超时提前返回（根因），同时移除所有 AI token 限制，直接 `await` 模型自然完成；兼容 `{response}` / OpenAI `choices` / `result.response` 三种输出形态；保留括号配对 JSON 提取与 `X-AI-Model` 响应头（见 `functions/api/routes/ai.ts`）。

**待验证**：需部署后跑 smoke，确认 12 个 AI 接口均返回 JSON；若仍失败，错误体会给出具体不可用模型，再定向调整模型列表。

### P0-2 SSL 检测接口挂死

**现象**：`/api/ssl-check?domain=github.com` 超过 30s 无响应。

**根因**：`crt.sh` 请求与直连 `HEAD` 均未设置超时；热门域名的证书透明日志响应体很大，上游可长时间不返回。

**修复**：两处外发请求增加 8s / 5s 超时，整体保证 ≤13s 返回 JSON（见 `functions/api/routes/ssl-check.ts`）。

## 4. P1 缺陷（本轮仅修与 502 相关项）

| 编号 | 问题 | 影响 | 本轮处理 |
|---|---|---|---|
| P1-1 | `ip / dns / exchange / headers-check / safeFetch` 外发请求无超时 | 上游挂起时请求被边缘终止，表现为 502/超时 | **已修**：统一加 `AbortSignal.timeout` |
| P1-2 | AI 输出解析过于脆弱 | 模型输出解释文字即 500 | **已修**：`parseAiJson` |
| P1-3 | API 响应契约不统一：`whois/ssl-check/headers-check` 返回裸对象，其余返回 `{success,data}` | 前端每个工具一套解析逻辑，新增接口易错 | 仅记录，不在本轮改 |
| P1-4 | `Env` 将 `CACHE/AI` 声明为必填 | fork 用户未绑定时类型失真 | 仅记录 |
| P1-5 | 元数据双源：`registry.ts` 144 条 + 144 个 `meta.ts` | `sync-meta.mjs` 只同步 `name/icon/category`，`description/tags/keywords/requiresApi` 会静默漂移 | 仅记录 |
| P1-6 | i18n 只覆盖外壳 | 切换到英文后 144 个工具内部仍为中文 | 仅记录 |
| P1-7 | `index.html` 生产环境 prefetch `/src/registry.ts` | 请求无效路径，浪费一次请求 | 仅记录 |
| P1-8 | 文档漂移 | `ARCHITECTURE.md` 仍写 R2、旧分包、旧模型 | 仅记录 |
| P1-9 | 测试缺口 | 无 UI/E2E 测试，AI 仅覆盖 3 个接口 | **已补**：Playwright E2E + smoke 全 AI 接口 |
| P1-10 | 文件完整性校验的 MD5 填充长度计算错误 | 上传任意文件时 MD5 与 SHA-256 都显示"计算失败"（`Promise.all` 被 MD5 异常拖垮） | **已修**：E2E 测试发现，修正为 `Math.ceil((len + 9) / 64) * 64` |

## 5. P2 观察

- 12 个 AI 工具页各自维护 loading/error/result 状态机，重复度高。
- `/api/proxy` 开放 CORS 且无速率限制，存在被外部当作开放代理滥用的风险（SSRF 防护已具备）。
- `EXCHANGE_API_KEY` 在 `Env` 中声明但未使用。
- `ip-api.com` 使用 HTTP 且为共享出口 IP，免费额度 45 req/min，存在 429 风险。
- 75 个工具仍带过期 `isNew` 标识（本轮已全部移除）。

## 6. 重构建议（本轮不实施）

| 编号 | 建议 | 收益 | 风险/前置条件 |
|---|---|---|---|
| R1 | `meta.ts` 作为唯一事实源，构建时用 `import.meta.glob` 生成 registry | 消除 144 条重复数据与漂移 | 需要改构建/测试脚本；属于中等改造 |
| R2 | API 统一 `{success, data, error, code}` 契约 + 共享 KV 缓存/超时/错误映射 helper | 前端解析统一，新增接口成本下降 | 需同步改 8 个前端工具 |
| R3 | AI 调用抽成 `functions/lib/ai.ts` | 模型候选、超时、解析、诊断集中管理 | 需在 P0 验证后进行 |
| R4 | AI 工具页共用 `useAiTask` + `AiResultPanel` | 12 份重复状态机收敛为 1 份 | 纯前端改造，可与 R3 同批 |

**触发条件**：R1 在下次批量新增工具前做；R2 在新增后端接口前做；R3/R4 在本轮 AI 502 修复验证通过后做。

## 7. 建议的后续优先级

1. 部署本轮修复 → 跑全量 smoke，确认 AI 与 SSL。
2. 处理 P1-3/P1-4（契约与类型），成本低、收益直接。
3. 评估 R1（元数据单一事实源）是否在 v1.7 工具扩展前落地。
4. i18n 要么补齐工具文案，要么移除英文切换入口，避免"假双语"。
