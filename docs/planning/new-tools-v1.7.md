# 新增工具规划（v1.7.0）

基于现有 144 个工具的覆盖缺口，按「使用频率 × 实现成本 × 依赖体积」排序。所有候选均已完成与现有工具的重复性核对。

## 一、缺口判断

现有工具覆盖已较完整，明显空白集中在三类：

1. **日常请求调试**：Cookie、WebSocket、HAR 等浏览器侧数据没有被解析
2. **国内办公场景**：金额大写、简繁转换等中文特色需求缺失
3. **可视化/图形化**：正则结构、图片差异、PDF 处理只有文本或单图能力

## 二、候选清单

| 优先级 | 工具 | 功能定位 | 依赖 / 体积 | 成本 | 验收标准 |
|---|---|---|---|---|---|
| P0 | Cookie 解析与生成 | 解析 `Cookie` / `Set-Cookie`，编辑后生成请求头；显示 Domain/Path/Expires/SameSite/HttpOnly/Secure | 无，纯前端 | 0.5 人日 | 解析 10 组真实样例；非法输入有明确错误；可复制为 `Cookie:` 头 |
| P0 | 人民币金额大写 | 数字金额转中文大写（含角分、零的处理、负数、上限） | 无 | 0.5 人日 | 表驱动 30 组（0、0.01、10.5、1000000.99、负数）；与银行写法一致 |
| P0 | 图片对比 Diff | 两张图叠加滑块对比 + 像素差异高亮 + 差异比例 | Canvas，无第三方 | 1 人日 | 同尺寸/不同尺寸均可对比；差异比例可复现；不阻塞主线程 |
| P1 | SVG → PNG | SVG 代码或文件转 PNG，可选倍率与透明背景 | Canvas，无第三方 | 1 人日 | 支持 1x/2x/4x；保留透明；导出文件可正常打开 |
| P1 | WebSocket 调试器 | 连接 ws/wss、发送文本/JSON、消息时间线、心跳与重连 | 原生 WebSocket | 1.5 人日 | 连接/断开/错误状态清晰；消息可复制；不因断线丢历史 |
| P1 | 正则可视化 | 将正则解析为铁路图/语法树，辅助理解复杂表达式 | `regexp-tree`（懒加载，约 60KB gzip） | 1.5 人日 | 支持分组/选择/量词/断言；非法正则提示位置；与 regex-tester 互相跳转 |
| P2 | HAR 分析器 | 上传 HAR，统计请求数、耗时分布、慢请求、失败请求、域名聚合 | 无 | 1 人日 | 支持大文件（>10MB）不卡死；可按状态码/域名筛选；导出 CSV |
| P2 | PDF 合并 / 拆分 | 合并多个 PDF、按页码范围拆分、删除页面 | `pdf-lib`（懒加载，约 120KB gzip） | 2 人日 | 合并顺序可调；拆分页码校验；输出文件可被主流阅读器打开 |
| P2 | 三路文本合并 | 对比 base/ours/theirs 并生成合并结果，标记冲突 | `diff3`（懒加载，约 15KB gzip） | 1.5 人日 | 自动合并无冲突段；冲突块高亮；可复制合并结果 |
| P2 | GraphQL 格式化/校验 | 格式化 query/mutation、语法校验、字段折叠 | `graphql`（懒加载，约 150KB gzip） | 1.5 人日 | 语法错误定位行列；格式化幂等；支持 schema 片段高亮 |

## 三、重复性核对

| 候选 | 现有相近工具 | 结论 |
|---|---|---|
| Cookie 解析 | `http-headers` 仅做 Header 说明 | 不重复 |
| 人民币大写 | 无金额类工具 | 不重复 |
| 图片对比 | `image-compress` / `image-convert` / `image-resize` 均为单图处理 | 不重复 |
| SVG → PNG | `svg-optimizer` 压缩、`svg-to-data-uri` 转 DataURI，均不导出位图 | 不重复 |
| WebSocket 调试 | `api-playground` 仅 HTTP；`json-rpc-test` 仅 JSON-RPC over HTTP | 不重复 |
| 正则可视化 | `regex-tester` 做匹配测试、`ai-regex` 生成正则，均无结构图 | 不重复 |
| HAR 分析 | 无 | 不重复 |
| PDF 处理 | 仅 `mime-types` 收录 pdf 类型 | 不重复 |
| 三路合并 | `text-diff` 仅两路对比 | 不重复 |
| GraphQL | 无 | 不重复 |

## 四、实施建议

1. **先做 3 个 P0**：均无第三方依赖、单页即可完成，能最快补齐日常调试与国内办公场景。
2. **P1 按依赖体积排序**：SVG → PNG 无依赖先做；WebSocket 需要处理连接生命周期，单独排期；正则可视化引入 `regexp-tree`，必须走工具级懒加载。
3. **P2 的 PDF / GraphQL 依赖较重**：只在确认有真实使用需求后引入，且必须在工具内 `await import()`，不得进入首屏或共享 chunk。
4. **每个工具必须走五步**：目录 + `meta.ts` + `index.tsx` + registry + `pnpm icons:gen && pnpm audit:meta --check && pnpm test`。禁止再出现非法图标或名称漂移。
5. **敏感数据**：Cookie 可能包含会话凭据，默认不写入 `HISTORY_ENABLED`；PDF/HAR 仅本地处理，不上传。

## 五、不建议新增

| 方向 | 原因 |
|---|---|
| 端口扫描 / 目录爆破 | 易被滥用，且与工具箱定位不符 |
| 在线 WHOIS 批量抓取 | 上游限流严重，维护成本高于收益 |
| 视频转码 / OCR | 依赖 WASM 体积过大（>2MB），破坏首屏与离线策略 |
| 账号体系与云端同步 | 涉及隐私与合规，现阶段保持纯本地 |
